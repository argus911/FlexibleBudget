                        四種查詢模式差異：

                        📄 年度預算查詢：單一年月，額外帶出前一年同期預算（去年至本月預算、去年年度預算及其差額），用於年度預算增減比較。查詢所有資料（含排除項目、含內部碳費）。

                        📈 跨年度預算查詢：可一次查多個年月（年月欄位以逗號分隔），或用起始年～結束年；連線年度取連線月份、其餘年度取12月。查詢所有資料（含排除項目、含內部碳費）。

                        🎯 營業項目別績效：
                        主表採用 VQRY2{交易機構}（比照 KPI_O2績效），
                        報表類別與項目代號取自 ACPGACOD d，並移除 ORDER BY、改加
                        OPTIMIZE FOR 1 ROW WITH UR，避免資料庫端 10 秒逾時 Operation cancelled。
                        SQL 以「預算與營收績效查詢」同構——
                        LEFT OUTER JOIN ACPGACOD d（GENACC+SUBACC+YEAR 三鍵）＋ SELECT DISTINCT 去重，
                        可在「查詢條件設定」自由組合多條件，例如總帳 4609＋報表類別 4＋項目代號 A →
                        a.GENACC LIKE '4609%' AND d.ACCTYP LIKE '4%' AND d.ITMCOD LIKE 'A%'；
                        總帳留空＝不限總帳（不再自動加 a.GENACC LIKE '5%'），
                        以免查詢報表類別 4（4 開頭營收科目）時條件互斥而查無資料；要只看成本費用請在「總帳」欄自行填 5。
                        不套排除條件。

                        📊 KPI_O2績效：以 KPI 要求之成本費用績效為主，
                        不含排除項目、含內部碳費。以連線年月為準，並與「列帳機構」連動（0000／0100／2040／4040…，逗號多筆，留空＝所有機構）。
                        主表採用 VQRY2{交易機構}，刪除 ITMDSC／RPTID（VQRY2 無此欄位，AMTTYP 亦一併移除），
                        項目代號改由 LEFT OUTER JOIN ACPGACOD d（GENACC+SUBACC+YEAR 三鍵）取得 d.ITMCOD。
                        加 SELECT DISTINCT，科目條件補回 SQL
                        ((SUBSTR(a.GENACC,1,1)='5' AND SUBSTR(a.GENACC,1,2) NOT IN ('5 ','59','57')) OR a.GENACC='570B')，
                        並新增 d.ACCTYP='55' 與 a.DIGITS=9；
                        明細帳重複（如 929F）由後端依 列帳機構+交易機構+總帳+明細帳+年+月 再收斂一次，避免聚合時金額加倍。
                        採三段單一年月的輕量 SQL（本年本月／前一年同月／前一年12月，皆無 GROUP BY、無 NOT(...)），
                        先撈所有科目資料，再由後端 Python 後製篩選「排除項目」與科目條件（碳費 470B／570B 不套排除條件），並合併「前一年度」；
                        前一年兩段為選用段，失敗只警告、本年度結果照常回傳。再由後端 Python 聚合，
                        產出本月動支數／本月動支率／累計動支數／累計動支率／上年度累積預算／二年度累計預算差額／N%年度預算(基本版)／
                        N%預算動支率(基本版)／去年同期累計動支數／YoY%／預算主管(DEPT)／排除考核項目(CONTROL) 等欄位；
                        470B/570B 之項目代號自動歸為 CO2；「預算主管」欄固定放在最後一欄（已移除與其重複的「預算主管單位」）。
                        搭配上方「📊 KPI_O2 考核版預算」上傳 Excel 後，
                        另外帶出 累計至{年月}預算(基本版/考核版)、累計動支率%(基本版/考核版)、得分(基本版/考核版)、
                        累計預算數差額(考核版-基本版)、本年度預算(考核版)、本年度動支率(考核版)%、剩餘可動支數(考核版)。

                        歷史年度分界＝連線年度 − 3：該年度(含)以前查 VQRY2H0000 歷史檔，之後查 VQRY6+交易機構；區間跨越分界時自動 UNION ALL 兩張表。
                        歷史檔沒有 RPTID / ITMCOD / ITMDSC，後端會自動補上 LEFT OUTER JOIN ACPGACOD 取得報表類別與分類代碼。

                        排除項目(XXX)：勾選欄已取消——「營業項目別績效」一律於 SQL 加上 AND NOT (SUBSTR(SUBACC,1,n) IN (...)) 由資料庫濾除；
                        「年度／跨年度預算查詢」不套用，僅由 CATEGORY 欄位標示 XXX。

                        ♻️ 內部碳費：勾選欄已取消，三種查詢一律含內部碳費。
                        年度／跨年度預算查詢比照桌面版預設 SQL，以 OR 分支併入單段：
                        ((GENACC LIKE '5%' AND d.ACCTYP='55') OR (GENACC='570B' AND SUBACC IN ('AA1ZZ','AA2ZZ') AND d.ACCTYP='CO2' AND d.ITMCOD LIKE 'A.02%'))。
                        營業項目別績效採兩段：第①段成本費用（GENACC 範圍條件走索引），第②段內部碳費（GENACC='570B' AND SUBACC IN ('AA1ZZ','AA2ZZ') AND d.ACCTYP='CO2' AND d.ITMCOD LIKE 'A.02%'），後端合併——避免 OR 跨欄位造成 Operation cancelled。

                        JOIN 說明：年度／跨年度預算查詢的現行檔 VQRY6 一律 LEFT OUTER JOIN ACPGACOD d（內建條件引用 d.ACCTYP / d.ITMCOD）；
                        營業項目別績效的成本費用段只在「有帶報表類別條件」或「查歷史檔」時才 JOIN，其餘維持不 JOIN 走 GENACC 索引；碳費段一律 JOIN（駆動條件極收斂，毫秒級）。
                        列帳機構為 4 碼時改用 = 比對以利索引。

                        歷史檔 VQRY2H0000 例外：該表沒有 RPTID / ITMCOD / ITMDSC 三個欄位（直接查會回 [SQL0205]），
                        故歷史段仍必須 LEFT OUTER JOIN ACPGACOD d 才取得報表類別與分類代碼：
                        d.ACCTYP（與現行檔有報表類別條件時的 JOIN 邏輯一致）、ITMCOD → d.ITMCOD，ITMDSC 無對應來源留空。
                        JOIN 鍵為 GENACC + SUBACC + YEAR 並限定 d.FILTYP = 'GACCN'（寫在 ON 而非 WHERE，
                        否則 LEFT JOIN 會退化成 INNER JOIN）—— 少了這兩者會對到多列，把歷史列複製成好幾筆而使金額被灌大。

                        📊 項目圖表 → 分類代碼(第一碼合計)（預設）：依 分類代碼(ITMCOD) 第一碼加總，
                        僅適用報表類別 55（A.用人費用／B.承攬及外包項目／C.行銷業務項目／D.客戶專案成本／E.維運項目／F.支援相關項目）；
                        總帳 470B/570B 或分類代碼 CO2 歸入 CO2.內部碳費；
                        要看 A.1 / E.3.1 這種完整代碼請改選「分類代碼(完整明細)」。
